The post-receipt — sealed to its backing proof

A post that passes the gate seals a content-addressed receipt: the post's hash, the build-receipt's hash, the backed claims. It verifies anywhere — and the gate refuses to seal a post that failed.

The post ledger — every claim we made, and what backed it

Each gate decision — shipped or refused — lands on a SHA-256 hash chain. This is the audit trail a regulator (or your own future self) asks for. Tamper with any entry and the chain breaks visibly.

Use it from your AI agent — the claim-receipt-gate skill

The same gate you just used on this page ships as one file an AI agent can run before it publishes anything: a release note, a README, a changelog, a launch post. The agent hands it the draft and the receipt of what was actually built; the gate answers SHIP or REFUSE and names every claim the receipt does not back. The agent's words never get past it on their own say-so.

Start here — three ways in

  1. In this page. Paste a draft and a receipt in the box above, press gate. Nothing leaves your browser.
  2. On the command line. Clone the repo, then node scripts/claim-receipt-gate.mjs examples/refuse.json. Exit 0 = SHIP, 1 = REFUSE, 2 = the input could not be used. The input is one JSON object: {"post": …, "receipt": {"url","live","ci","witness","facts"}, "sealedAt"?}.
  3. As an agent skill. Give your agent SKILL.md and the script. Its rule: before posting, run the gate; on REFUSE, fix or cut each named claim and run it again; never publish on REFUSE.

What it does for your business

  • CEO / founder: one overclaim in a launch post costs more trust than ten true ones earn. This makes the overclaim impossible to ship by accident.
  • Marketing lead: write at AI speed; the gate is the reviewer that never gets tired and never waves a number through.
  • CTO / CISO: deterministic, no model in the loop, no network, no dependencies, MIT source you can read in an afternoon. It runs where your agent runs.
  • Compliance / legal: every gate decision can be appended to a hash-chained ledger and every shipped post sealed to its backing receipt — an audit trail of what you claimed and why you were allowed to.
  • Roll-out: add one step to the agent's publish flow (run the gate, honour the exit code). Day one, no training, no data leaves your machines.

Risks, answered straight

  • It does not fetch. Whoever builds the receipt must probe for real (the 200, the CI result, the witness run). A faked receipt gets a faked pass; the gate proves the post matches the receipt, not that the receipt is true.
  • It checks the checkable only. "Fastest on the market" is not a link, score, percent, live, CI or verified claim, so it is not caught. That is a stated limit, not a hidden one.
  • Percent matching is textual. A percent is backed when a receipt fact contains it; write facts as measured.

How it stays honest

  • It checks the checkable, and only that. URLs, K/N witness scores, CI-green, "live", percentages against measured facts. A number that isn't a score or a percent ("seven layers") is left alone. It does not judge whether the prose is persuasive — that isn't its job.
  • No model in the loop. Every decision is a deterministic rule against the receipt. A model grading marketing copy is exactly the false confidence this refuses.
  • It composes, it doesn't replace. The estate's generators still write the post (fallpost, fallgravity). This is the gate that sits after them and before the rail: draft → post-proof → fallscrub → the rail. No receipt, no post.
  • The rail is already built. The sanctioned Meta Graph rail (rate-disciplined, token-redacted) is whole except one paste — a Page Access Token the owner sets up once. This gate is what makes that rail's posts provable.

Honest limits (v1)

  • Checkable claims only. It backs facts a receipt can carry; it does not fact-check free prose or judge tone. The one-line "what it does" rides on trust, capped and visible.
  • Tamper-evident, not yet signed/anchored. The post-receipt and ledger hash-verify; Ed25519 issuer signing + an external anchor is v2.
  • You bring the receipt. The real 200 / CI-conclusion / witness-verdict probes run in the rail's runner; this kernel adjudicates the draft against what those probes found.
  • The live send needs the one-time channel connect. Auto-posting to a real page needs its Page Access Token, granted once by the account owner — it can't be faked. Not audited. MIT.
